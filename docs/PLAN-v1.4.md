## 0. 总原则

1. **不引入构建工具**：继续「原生 HTML + 经典脚本 + 按需 ESM」，不引入 Vite/Webpack。
2. **零新增网络请求**：新增视觉、音效、分享图全部由 CSS / Canvas / WebAudio 生成。
3. **不强依赖大模型**：解读由本地规则引擎完成；LLM 仅作为未来可选增强。
4. **可回退**：每批独立版本号 + tag，视觉改动不破坏现有 DOM 契约。

## 1. 方案 A · 2D 翻牌「仪式感」

### 1.1 现状

- 翻牌 = `.tarot-card.flipped .tarot-card-inner { rotateY(180deg) }` 一条过渡
- 入场 = `dealIn` 0.5s；洗牌 = 整体 `shuffleJump`
- 卡背 = 同一段 CSS 渐变，78 张完全相同
- 翻牌后无任何「事件反馈」，其他牌不分心，逆位只是图片倒置

### 1.2 目标状态（一次翻牌的完整时间线）

| 时间 | 事件 | 实现 |
|---|---|---|
| 0ms | 卡牌抬起 + 轻微放大 | `transform: translateY(-10px) scale(1.03)` |
| 0–700ms | 绕 Y 轴 180° 翻转 | 现有 `rotateY`，缓动改为 `cubic-bezier(.34,.08,.2,1)` |
| 0–650ms | 金色光环从卡牌中心扩散 | `.tarot-card.flipping::after` + `@keyframes flipBurst` |
| 150–550ms | 一道高光扫过卡面 | `.tarot-card-inner::after` + `@keyframes sheenSweep` |
| 0–700ms | 其余未翻牌后退变暗 | `.card-layout.has-reveal .tarot-card:not(.flipped)` → `opacity .55 / scale .97` |
| 700ms | 牌面定妆：0.94 → 1，亮度回落 | `.is-revealed` + `@keyframes revealSettle` |
| 820ms | 位置标签淡入 | `.pos-label` 延迟过渡 |
| 可选 | 合成音效「沙」 | WebAudio 噪声 + 带通滤波 + 衰减包络（无素材） |

逆位差异：翻开的瞬间角标从紫光扫过，卡面叠加一层极淡紫雾（`mix-blend-mode` 可选，失败可忽略）。

### 1.3 实现要点

- **状态类**：`.is-flipping` / `.is-revealed` / 布局级 `.has-reveal`；动画结束用 `transitionend` + 兜底 `setTimeout` 双保险（老内核）。
- **只动 `transform` / `opacity`**：不触发布局重排；`will-change` 仅在翻转期间加，结束即移除，避免长期占显存。
- **音效**：`AudioContext` 在首次用户手势时惰性创建；提供静音开关（`localStorage`），默认可关。
- **降级**：`prefers-reduced-motion: reduce` 下跳过光环与高光，只保留 0.01s 翻转。
- **移动端**：无 hover，光环与定妆照常；点击阈值沿用现有逻辑。

### 1.4 涉及文件

| 文件 | 改动 |
|---|---|
| `css/style.css` | 新增 4 组 keyframes、3 个状态类、`::after` 高光层 |
| `js/app.js` | `flipCard()` / `flipAll()` 增加状态类与 `transitionend`；音效模块 |
| `index.html` | 可选：音效开关按钮（放在抽牌操作栏） |

### 1.5 验收

- [ ] 单张翻牌肉眼可见 5 个层次（抬升/光环/高光/定妆/标签）
- [ ] 连续点「全部翻开」不错位、光环不叠成一片
- [ ] `prefers-reduced-motion` 下无动画残留
- [ ] 翻牌期间 60fps（Chrome Performance 面板无长任务）

**价值：高 ｜ 成本：低 ｜ 风险：低**

## 2. 方案 B · 离线解读引擎

### 2.1 为什么值得做

现在是「每张牌贴一段通用牌义」，正位和逆位同时展示，信息噪音大，也不像一次「解读」。
老式塔罗软件的做法是 **词典 + 位置语义 + 模板 + 规则**，完全离线也能产出连贯文字。

### 2.2 数据层扩展

**卡牌**（`js/data/cards.js`）新增字段：

| 字段 | 取值 | 来源 |
|---|---|---|
| `element` | fire / water / air / earth | 花色直接映射（权杖火/圣杯水/宝剑风/星币土）；大阿卡纳手工指定 |
| `numKey` | seed / balance / growth / structure / change / harmony / will / mastery / completion / overflow | 由 `num` 推导（1–10） |
| `yesNo` | -1 / 0 / +1 | 大阿卡纳手工；小阿卡纳按花色+数字推导 |
| `advice` | 一句祈使句 | 首批手工写 22 张大阿卡纳 + 16 张宫廷牌，其余由 `numKey` 模板生成 |
| `timing` | fast / slow | 可选，用于「时间流」牌阵 |

> 40 张小阿卡纳不必逐张写建议：用「数字语义 × 花色语义」矩阵生成，
> 这正是老软件能覆盖 78 张牌又不需要海量文案的原因。

**牌阵**（`js/data/spreads.js`）`positions` 新增 `role`：

```
past / present / future / self / other / relation / obstacle / environment /
advice / outcome / hope / fear / action / result
```

每个 role 自带：语气（已发生/正在/将发生）、句式模板、权重。

### 2.3 规则层（首批 10 条）

| 规则 | 触发条件 | 输出示例 |
|---|---|---|
| R1 大阿卡纳密度 | ≥ 50% | 「本次牌阵有 5 张大阿卡纳，议题落在命运层面，不是日常小事。」 |
| R2 逆位密度 | ≥ 60% | 「逆位偏多，能量内耗或延迟，事情不会按表面节奏推进。」 |
| R3 花色失衡 | 某花色 ≥ 50% | 「权杖占主导，行动力是主线；情感与物质是配角。」 |
| R4 元素冲突 | 火+水 / 风+土 同时出现 | 「火水相冲：冲动与情绪在拉扯，先安顿情绪再行动。」 |
| R5 数字重复 | 两张牌 `num` 相同 | 「两张 3：表达与成长的议题被重复强调。」 |
| R6 牌对规则 | 命中 20 组手工牌对 | 「死神 + 太阳：一次结束之后紧跟重生。」 |
| R7 位置-牌性匹配 | 建议位出现隐士/女祭司等 | 「建议是向内看，而不是继续向外求解。」 |
| R8 首尾呼应 | 第 1 张与最后一张元素相同/相冲 | 「起点与结果同属水，情绪线贯穿始终。」 |
| R9 缺失花色 | 某花色完全缺席 | 「完全没有星币：现实落地与资源分配被忽略。」 |
| R10 结果强度 | 结果位大阿卡纳 + 正位 | 「结果位是正位大阿卡纳，方向确定性较高。」 |

单次最多输出 3 条规则，按「信息量 × 置信度」排序，避免堆砌。

### 2.4 模板与合成

句式模板（每个 role 3–5 个变体）：

```
在「{position}」，{card}（{orientation}）出现：{cardLine}。
作为{roleLabel}，它提示{roleClause}。
```

合成结构：

1. **总览**：1–2 句，来自 Top2 规则 + 花色基调。
2. **逐位**：每位 2–3 句（牌义 + 位置语境 [+ 1 条相关规则]）。
3. **建议**：1–2 句，来自 `advice` 字段 + 主导元素 + 结果位。
4. **免责**：沿用现有文案。

质量约束：

- 同一次解读内不重复同一 opener；模板变体按本次随机种子选取。
- 逆位不写「将会成功」这类确定性正向句（规则冲突检查）。
- 3 张牌 300–500 字，10 张牌 800–1200 字，按张数线性控制。

### 2.5 示例输出（三张牌 · 时间流）

> 过去位是逆位圣杯五：失落仍在回响，但已经开始收拢。现在位是正位权杖八：节奏突然加快，
> 消息与行动一起到来。未来位是正位太阳：方向清晰，结果偏明朗。
> 牌阵中火元素占主导，行动力是主线；逆位只有一张，说明内耗正在退场。
> **建议**：先把要发的消息发出去，再处理情绪；今天的行动比思考更有效。

### 2.6 涉及文件

| 文件 | 改动 |
|---|---|
| `js/data/cards.js` | 增加 element / numKey / yesNo / advice（分批补齐） |
| `js/data/spreads.js` | `positions` 增加 role |
| `js/data/lexicon.js`（新） | 数字语义、花色语义、role 句式、牌对表 |
| `js/reading/engine.js`（新） | 纯函数：`compose(spread, draw) → { overview, sections, advice, text }` |
| `js/app.js` | `renderReading` 改用引擎输出；保留旧字段兜底 |
| `index.html` | 增加一个经典 `<script>`（引擎 + 词典） |

### 2.7 验收

- [ ] 78 张牌 × 正逆位都能生成不报错的解读
- [ ] 同一牌阵连续 10 次，开场句不重复
- [ ] 3 张牌生成耗时 < 5ms（纯字符串拼接）
- [ ] 旧数据（历史记录）仍可渲染
- [ ] 文案无「正位/逆位同时讲」的噪音

**价值：最高 ｜ 成本：高 ｜ 风险：中（文案质量需人工抽检）**

## 4. 方案 D · 分享海报 + 历史增强 + 工程化

### 4.1 分享海报（零后端）

- Canvas 1080×1920：深空渐变背景、牌阵名、日期、卡面缩略图（最多 10 张）、解读摘要、站点地址。
- 字体用已加载的 Cinzel / Noto Serif SC；绘制前 `await document.fonts.ready`。
- 卡图同源，无 CORS 问题；`canvas.toBlob('image/jpeg', 0.92)`。
- 移动端优先 `navigator.share({ files })`，桌面端下载 PNG。
- 入口：解读页新增「生成分享图」按钮。

### 4.2 历史记录

- 按牌阵分类筛选、按牌名搜索。
- 单条导出 / 全部导出 JSON。
- 存储迁移：localStorage → IndexedDB（容量更大、结构化查询），首次启动自动迁移并保留回退。

### 4.3 工程化

- 回归脚本入库：`tests/regress.mjs` + `package.json` 的 `npm run test:e2e`（Chrome 路径可用 `CHROME_PATH` 覆盖）。
- GitHub Actions：push `main` → 跑回归 → `cloudflare/wrangler-action` 部署 Pages。
  需要在仓库 Secrets 配置 `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`。
- 字体子集校验脚本：扫描 HTML/JS 文案字符，与 woff2 覆盖表比对，缺字直接失败
  （v1.3.6 就因新增「查」字翻过车）。
- 无障碍：卡牌 `tabindex=0` + Enter/Space 翻牌；模态焦点陷阱；解读页 `aria-live` 播报。

**价值：中 ｜ 成本：中 ｜ 风险：低**
